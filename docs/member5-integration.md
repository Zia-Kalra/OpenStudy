# Member 5 — Teacher Dashboard and AI Integration (Phase 1)

## 1. What Member 5 implemented

Phase 1 delivers the teacher portal foundation without replacing other members’ work:

- Teacher Dashboard JSP (`/teacher/dashboard`) with reusable sidebar, navbar, and footer fragments
- Layered Spring architecture: controller → service → data provider → DTOs
- Mock dashboard data so development can continue before MySQL is ready
- A `mock` Spring profile that starts without a live database
- Shared `AIService` contract for Members 2 and 3
- Gemini REST integration (official `generateContent` API) plus a clearly labeled mock AI provider
- Configurable navigation paths for modules owned by Members 1–4
- Tests for the dashboard service, mock provider, AI validation, and Gemini error mapping

This work does **not** implement login, quizzes, assignments, submissions, R analytics, or schema changes.

## 2. How to run the dashboard in mock mode

From the repository root (Windows):

```powershell
.\backend\mvnw.cmd -f backend\pom.xml test
.\backend\mvnw.cmd -f backend\pom.xml spring-boot:run "-Dspring-boot.run.profiles=mock"
```

Then open:

- http://localhost:8080/teacher/dashboard
- Existing health check: http://localhost:8080/api/test

`/api/db-test` is disabled on the `mock` profile because there is no DataSource.

Empty-state demo (optional):

```properties
openstudy.dashboard.mock-scenario=empty
```

## 3. How to configure Gemini securely

Set the API key in the environment. Never commit it, never put it in JSP/JS, and never log it.

For a working local `backend/.env` loader and isolated verification endpoint, follow
[Gemini local setup](gemini-local.md). Store the real key only in the ignored
`backend/.env`, then launch with `backend/run-gemini-local.ps1`. Creating the file
without the launcher does not load it into Spring Boot.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\backend\run-gemini-local.ps1 -Port 8081
```

Enable the live provider:

```properties
openstudy.ai.provider=gemini
openstudy.ai.gemini.api-key=${GEMINI_API_KEY:}
openstudy.ai.gemini.model=${GEMINI_MODEL:gemini-3.8-flash}
```

The implementation calls:

The default `gemini-3.8-flash` was verified against Google's official model catalog
on 13 October 2026: https://ai.google.dev/gemini-api/docs/models . Override it with
`GEMINI_MODEL` when the team selects another supported model.

`POST {baseUrl}/models/{model}:generateContent`

with header `x-goog-api-key` as documented by Google AI for Developers.

If the key is missing, `GeminiAIService` fails with `MISSING_API_KEY`. The mock provider is used when `openstudy.ai.provider=mock` (the Phase 1 default). Mock responses are prefixed with `[DEMO PLACEHOLDER — not generated by Gemini]`.

## 4. Java interfaces other members should use

### Shared AI (Members 2 and 3)

```java
com.openstudy.openstudy.service.ai.AIService
```

- `List<GeneratedMCQDTO> generateMCQs(MCQGenerationRequest request)`
- `AssignmentEvaluationResult evaluateAssignmentAnswer(AssignmentEvaluationRequest request)`

Inject `AIService`. Do not construct `GeminiAIService` directly.

Request/response types:

- `com.openstudy.openstudy.dto.MCQGenerationRequest`
- `com.openstudy.openstudy.dto.GeneratedMCQDTO`
- `com.openstudy.openstudy.dto.AssignmentEvaluationRequest`
- `com.openstudy.openstudy.dto.RubricCriterionDTO`
- `com.openstudy.openstudy.dto.AssignmentEvaluationResult`

Errors are `AiServiceException` with `AiErrorCode`.

### Validation and compatibility

The `AIService` signatures and error-code enum are unchanged. Both providers validate
direct Java calls before generating output or sending HTTP requests. Invalid requests
throw `VALIDATION_FAILED`; callers must handle this alongside upstream failures.

- MCQ count: 1–20; difficulty: EASY, MEDIUM, or HARD (case-insensitive).
- Required subject/topic limits: 200/500 characters; optional instructions: 2,000.
- Required evaluation question: 10,000 characters; student/model answers: 20,000 each.
- Maximum marks must be finite and positive. Rubrics are optional; at most 20 criteria
  with distinct names (200 characters), required descriptions (2,000), and finite positive
  marks whose total does not exceed the assignment maximum.
- MCQ results require the exact requested count and four nonblank distinct options;
  the correct answer is returned using the matching option's canonical text.
- Evaluation scores use two decimal places with HALF_UP rounding. They remain between
  zero and the original maximum; a fractional maximum can cap the score down to the
  largest two-decimal value within that maximum. Adjustments are explicitly flagged.
- Blocked, truncated, and unsuccessful Gemini completions throw `UNEXPECTED_RESPONSE`.
  Missing/malformed JSON fields throw `INVALID_JSON`. Messages exclude upstream payloads.
- Navigation properties accept paths starting with one slash, not external URLs,
  executable schemes, backslashes, or control characters. JSP attributes are HTML-escaped.
- Unknown placeholder module identifiers resolve to the generic `module` placeholder.

The grading system instruction treats student answers as untrusted data. This reduces
prompt injection risk but does not replace mandatory teacher review.

Members 2 and 3 must still HTML-escape AI text in their own views and keep mock outputs
out of final persistence/grading workflows. Never enable HTTP-client DEBUG body logging
for real student answers or API credentials.

**Persistence rules**

- Member 5 does not save MCQs or evaluations.
- Member 2 reviews generated questions, then stores them.
- Member 3 keeps final grading authority and stores marks.

## 5. Routes owned by Member 5

| Route | Owner | Purpose |
| --- | --- | --- |
| `GET /teacher` | Member 5 | Redirects to the dashboard |
| `GET /teacher/dashboard` | Member 5 | Teacher Dashboard |
| `GET /teacher/coming-soon?module=` | Member 5 | Integration placeholder only |
| `GET /api/test` | existing | Backend smoke test |
| `GET /api/db-test` | existing | JDBC smoke test (not on `mock`) |

Failed teacher pages and `/api/*` errors render through the shared error handler.
HTML uses `teacher/error.jsp` with a reference id and no stack traces. JSON uses
`{success,status,code,message,referenceId,retryable}`. Database outages map to 503;
Gemini `AiServiceException` maps to 4xx/5xx without dummy AI content.

Do not add competing quiz, assignment, analytics, or login controllers on top of these.

### Local regression checks

Run `backend/mvnw.cmd -f backend/pom.xml test` for the full Java suite. It includes
localhost embedded-Tomcat JSP rendering, XSS escaping, mock-profile isolation, request
validation, response validation, and mocked Gemini failures. No live Gemini requests are made.

Run `node --test backend/src/test/javascript/teacher-dashboard.test.cjs` for the five
mobile-navigation keyboard/focus/state tests. These use Node's built-in test runner and
require no frontend dependency installation. Browser/screen-reader acceptance testing
remains a separate integration check.
